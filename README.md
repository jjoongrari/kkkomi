# Квартирник Коми

Мобильная игра о ценах продажи квартир в Республике Коми: 10 случайных объявлений, галерея, оценка бегунком и сравнение с ценой продавца. Отдельный проект для публикации по новой ссылке. Исходный «Медиакоми» не требуется.

Next.js + TypeScript + Tailwind, статический экспорт, без API, базы данных, внешних шрифтов и UI-библиотек. Основной цвет — `#012D6E`. Типографика и строгая сетка вдохновлены сайтом НИУ ВШЭ; его логотип и фирменные шрифты не используются.

## Запуск

Нужен Node.js 22.18+ и npm.

```bash
npm ci
npm run dev
```

Откройте http://localhost:3000. Проверенная производственная сборка:

```bash
npm run check
npm start
```

`npm run check` проверяет TypeScript, правила игры и CSV, данные, статическую сборку, HTTP-заголовки и доступность каждой фотографии. `npm start` служит только для локального просмотра готовой папки `out`, серверная часть приложению не нужна.

## Опубликовать дубль на GitHub Pages

1. Создайте **новый пустой публичный репозиторий** с любым именем, например `kvartirnik-komi`. Не добавляйте в нём README, лицензию или gitignore.
2. Распакуйте архив. Откройте терминал в папке, содержащей `package.json`.
3. Архив уже содержит отдельную историю Git и готовый коммит. Подключите **адрес нового репозитория**, заменив `USERNAME` и `NEW_REPOSITORY`:

   ```bash
   git remote add origin https://github.com/USERNAME/NEW_REPOSITORY.git
   git push -u origin main
   ```

   Если ваша программа распаковки не сохранила папку `.git`, выполните сначала:

   ```bash
   git init -b main
   git add .
   git commit -m "Create Kvartirnik Komi game"
   ```

4. На GitHub откройте **Settings → Pages → Build and deployment → Source → GitHub Actions**.
5. Откройте **Actions → Publish Kvartirnik Komi → Run workflow → main → Run workflow**. Это также перезапускает публикацию после включения Pages, если первая попытка успела завершиться ошибкой.
6. После успешной сборки адрес появится в **Settings → Pages**: `https://USERNAME.github.io/NEW_REPOSITORY/`.

Следующие push в `main` обновляют сайт автоматически. Имя папки репозитория и URL не зашиты в код: workflow получает `base_path` от `actions/configure-pages`. Вручную менять пути фотографий не нужно. Для самостоятельной проверки подкаталога:

```bash
NEXT_PUBLIC_BASE_PATH=/new-repository npm run build
npm run test:http
npm start
```

Затем откройте http://localhost:3000/new-repository/. После такой проверки обычная сборка без переменной снова создаст сайт для корня домена.

## Данные и актуальность

Источник — предоставленный CSV `creative_hse_2026 - квартиры коми.csv`, сохранённый без изменения в `source/original-komi.csv`: 50 объявлений, город Инта. В игру включены 35 квартир с минимум двумя локальными фотографиями. 15 строк без нескольких снимков исключены, список ID сохранён в `source/verification.json`.

В исходнике нет поля статуса. **6 ноября 2026 года владелец подборки подтвердил: «Да, список актуален».** Поэтому для этой версии выставлены `active=true`, `checkedAt=2026-11-06`, `verificationSource=owner_confirmation`. Независимая проверка доступности страниц не выполнена: площадка не предоставила доступ к содержимому. Игра отбирает активные записи по сохранённому подтверждению, но не проверяет площадку онлайн при старте. Устаревшие записи нужно отключать и пересобирать сайт. Статическая версия GitHub Pages не может сама достоверно контролировать статус чужих объявлений.

Цены — полная стоимость **продажи**, в рублях. Это не аренда и не цены сделок. Поля и возможные неточности первичного источника, включая необычные значения площади, не исправлялись догадками.

Фотографии настоящие, скачаны из ссылок в таблице, сохранены в WebP без увеличения исходного разрешения 208 × 208. Это небольшие превью, поэтому на большом экране детализация ограничена. Для увеличения качества замените их исходными снимками с теми же именами. Внешние фотосерверы при игре не вызываются; загружается только текущий снимок галереи. Все фотографии вместе занимают меньше 1 МБ.

## Правила и подсчёт

- Каждый запуск: 10 случайных разных активных квартир Коми с минимум двумя фото; ранее выбранная цена не влияет на выбор следующей квартиры.
- Бегунок линейный, шаг 1 000 ₽. Диапазон общий для всей подборки, чтобы не подсказывать ответ. Начальное положение — медианная цена подборки. Первый запуск мягко демонстрирует движение; при `prefers-reduced-motion` анимация отключается.
- За квартиру: `round(100 × max(0, 1 − abs(оценка − цена) / цена))`. За игру 0–1 000 баллов. Одинаковая процентная ошибка даёт одинаковые баллы при завышении и занижении.
- 850–1 000 баллов: **Адекватный квартирант**. Ниже 850: больше занижений — **Жадный студент**, больше завышений — **Транжира**. При равном числе сравниваем сумму относительных знаковых отклонений; при нулевой сумме — знак наибольшего относительного отклонения (при равных величинах — первого по порядку).
- `разница = оценка − цена`. Положительная — оценка **больше**, отрицательная — **меньше** цены продавца. Нулевая — точное попадание.
- Переплата: сумма всех положительных разниц. Недоплата: сумма модулей отрицательных разниц. Общий баланс: переплата минус недоплата. Это гипотетические суммы оценок игрока, деньги не списываются.
- После ответа появляются реальная цена, разница, баллы и ссылка на исходное объявление. По завершении доступны разбор всех ответов и новая игра.

## Заменить таблицу и фотографии

В интерфейсе «Своя таблица» можно загрузить CSV и выбрать сразу несколько фото: данные обрабатываются локально и живут до перезагрузки. Для постоянной замены положите фотографии в `public/images`, подготовьте CSV по `public/data/template.csv`, затем выполните:

```bash
npm run import:csv -- /полный/путь/table.csv
npm run check
```

Импорт не назначает активность автоматически. Неподходящие строки исключаются, нужно минимум 10 подходящих. Поля CSV:

| Поле | Значение |
| --- | --- |
| `id` | Уникальный ID: латинские буквы, цифры, `_`, `-` |
| `title`, `location` | Название и адрес |
| `price`, `area` | Целая положительная цена в ₽ и положительная площадь |
| `region` | `Республика Коми` |
| `propertyType`, `dealType` | `apartment`, `sale` (значения по умолчанию, если поля не указаны) |
| `active` | `true` только после подтверждения актуальности |
| `checkedAt` | Дата подтверждения `YYYY-MM-DD` |
| `verificationSource` | `owner_confirmation` или `page_check` при фактической проверке страницы |
| `sourceUrl` | HTTPS-ссылка на Avito, Cian или Яндекс Недвижимость |
| `images` | 2–5 локальных путей через `;`, например `/images/a.webp;/images/b.webp` |
| `floor`, `floors`, `city` | Дополнительные сведения; город по умолчанию — Инта |

Для CSV с запятой пути с `;` остаются внутри одной ячейки. Поля с запятыми заключайте в двойные кавычки. Формат JSON для сборки — `public/data/listings.json`. Метаданные подборки — `public/data/catalog-meta.json`.

## Безопасность и другие хостинги

Сборка выносит исполняемые inline-скрипты Next.js в локальные файлы и добавляет CSP через meta. Подготовлены CSP, Referrer-Policy, X-Frame-Options, X-Content-Type-Options: nosniff и Permissions-Policy: `vercel.json`, `netlify.toml`, `nginx-security.conf` и `out/_headers`. Локальный сервер выдаёт все пять HTTP-заголовков.

**GitHub Pages не поддерживает настройку произвольных HTTP-заголовков.** Там действует встроенная meta-CSP; ограничения frame-ancestors/X-Frame-Options и остальные HTTP-заголовки требуют хостинга с поддержкой заголовков. Для Vercel используйте `npm run build` и директорию `out`, для Netlify настройки уже в файле проекта. При переносе на собственный Nginx подключите предоставленный файл заголовков.

Фронтенд не отправляет пользовательские оценки на сервер. LocalStorage хранит только факт демонстрации бегунка. Клиентский прототип содержит цены в статических данных и не предназначен для соревнований с защитой от просмотра ответов.
